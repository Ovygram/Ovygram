Создай или обнови интерфейс Ovygram по задаче в конце этого промпта. Ovygram — десктопный клиент на базе Telegram Desktop. Прочитай AGENTS.md и docs/ui-preview.md в репозитории Ovygram. Для плагина используй компоненты из Desktop SDK.

Цель экрана

- Определи, что человек хочет сделать, какое действие ему нужно выполнить чаще всего и как он поймёт, что оно сработало.
- Выбери подходящий формат. Компактная модалка подходит для одного решения, отдельная страница — для длинного списка или настроек, отдельное окно — для работы рядом с основным приложением.
- Используй бриф и референсы из текущего запроса. Если они расходятся, отдай приоритет явному требованию из текста. В конце назови решение, которое повлияло на результат.

Нативный стиль

- Используй существующие компоненты, иконки, отступы и цвета активной темы Telegram. Тёмная тема — удобная отправная точка. Сохрани читаемость в светлой теме и при масштабе 125%.
- Заголовок, основной текст, подсказки, метаданные и действия должны различаться по роли. Подсказки делай приглушёнными. Подпись поля должна оставаться понятной и после ввода значения. Синий акцент используй для главного действия, реальных переходов и принятой в проекте навигации.
- Используй единый левый край, одинаковые отступы внутри однотипных элементов и иконки одного размера. Оставляй только те подписи и элементы, которые объясняют действие, состояние или помогают навигации.
- Показывай описание целиком, с переносом по словам. Высота диалога следует за содержимым. При переполнении прокручивается его тело, а заголовок и действия остаются доступны.

Действия и состояния

- Используй максимум одну заметную основную кнопку. Если требуется сначала выбрать один из нескольких равноправных объектов, оставь их действия нейтральными до выбора. Для отмены, возврата и закрытия используй нативный паттерн окна.
- Обычные действия объединяй в компактные строки или в один блок кнопок. Опасное действие отделяй и выделяй цветом темы. Состояния передавай текстом и, при необходимости, иконкой или цветом.
- Убирай повторяющиеся данные. Для сравнения версий показывай полные сведения о новой версии и короткие строки установленных экземпляров. Разделы, действия и подсказки показывай там, где они уместны для текущего состояния.
- Если настройки находятся на другой поверхности, добавь явный переход. В SDK это может быть Link в create_settings() с обработчиком, который открывает нужное окно.

Палитра тёмных карточек Ovygram

Для карточек настроек плагинов используй цвета из таблицы.
Эти значения задают обычное состояние элементов. Для светлой темы бери
соответствующие цвета активной темы Telegram.

| Роль | Текст или иконка | Фон | Обводка |
| --- | --- | --- | --- |
| Основная кнопка, например «Выбрать сервер» | #F0F7FC | #3375AA | — |
| Вторичная кнопка, например «Обновить список» | #6493BD | #18242F | #507B9C, 1 px |
| Опасное действие, например остановка или удаление | #DE7D7A | #3A2D33 | — |
| Копируемый IP-адрес SOCKS5 или HTTP | #86A7C5 | #293C4A | — |

В Desktop SDK укажи `Button(palette="ovygram")` и вариант по роли:
`primary`, `secondary`, `danger`, `trash` для кнопки с корзиной
или `code` для моноширинной плашки IP.

Для залитой вторичной кнопки «Проверить обновления» используй
`Button(variant="subtle")`. Этот вариант берёт заливку и текст активной
темы и радиус 8 px из того же стиля, что и список плагинов. Стиль
действий Ovygram и фиксированные HEX-цвета карточек хранятся в
`Telegram/SourceFiles/ovygram/plugin_management.style`.

Проверка в облаке

- Собери и открой экран через tools/ovygram/ui-preview. При первом запуске в облачной Linux-среде подготовь зависимости командой tools/ovygram/ui-preview --setup по инструкции проекта.
- Для окна клиента запусти подходящий --scenario или добавь его. Для плагина передай --plugin с путём к .ovyplugin или .ovyzip. При необходимости используй --menu с подписью пункта или --setting с ключом действия. Для проверки клика в предпросмотре можно передать --click с подписью элемента.
- Используй тестовые данные и временный профиль. Проверь основной сценарий и подходящие граничные случаи, например длинный текст, узкое окно, пустые данные, ошибку, смену темы или масштаба. Для интерактивного экрана проверь результат основного действия.
- Сохрани скриншоты через --screenshot, открой их и сверяй с брифом. Исправь замеченные проблемы. В ответе приложи скриншоты, перечисли выполненные проверки и точно укажи, что потребовало отдельной проверки в полноценном клиенте.

# Справочник точек перехвата

Все места, где плагин может вмешаться в работу клиента или узнать о
происходящем. Подробности — в [SDK](sdk.md) и [`desktop.ui`](ui.md).

Обработчики интерфейса и синхронные обработчики событий вызываются в
главном потоке, `async def` запускается как управляемая задача плагина.
Всё регистрируемое снимается при выгрузке плагина.

## Сеть и данные

`self.add_hook(point, callback, priority=0, request=None)` — синхронный
обработчик, возвращает `HookResult`. `request` фильтрует по имени TL-метода.

| Точка | Когда | Что можно |
| --- | --- | --- |
| `before_send` | Перед отправкой сообщения, медиа, альбома, пересылки, inline-результата | Изменить текст, подпись, вложения, параметры; отменить |
| `before_rpc` | Перед любым прикладным запросом | Изменить поля запроса; отменить |
| `after_rpc` | После ответа на прикладной запрос | Изменить ответ или ошибку; восстановить ошибку |
| `before_updates` | Перед применением пакета `Updates` от сервера | Изменить пакет; пропустить (`CANCEL`) |

`self.subscribe(event, callback)`:

| Событие | Когда |
| --- | --- |
| `new_message` | Новое сообщение, в том числе своё и догруженное |
| `edited_message` | Изменение сообщения |
| `deleted_message` | Удаление сообщений |
| `account_changed` | Переключение активного аккаунта |
| `accounts_changed` | Вход, выход, изменение списка аккаунтов |
| `chat_changed` | Открытие или закрытие чата в окне |

## Интерфейс плагина

| Источник | Обработчик |
| --- | --- |
| `Button(on_click=...)` | Нажатие |
| `Input(on_change=...)` | Правка пользователем |
| `Switch(on_toggle=...)` | Переключение |
| `Canvas(on_click=...)` | Нажатие с координатами |
| `Surface(on_close=...)` | Закрытие окна, раздела, полосы или холста (пользователем, историей окна, при ошибке) |

## Интерфейс Telegram — `desktop.ui`

| Функция | Когда вызывается обработчик | Можно заменить действие Telegram |
| --- | --- | --- |
| `add_menu_item(menu, ...)` | Выбор пункта в главном меню, меню чата, профиля или сообщения | — |
| `add_panel_button(panel, ...)` | Нажатие своей кнопки в верхней панели чата или строке ввода; `PanelContext` | — |
| `element(name).on_click(...)` | Нажатие на встроенную кнопку | `replace=True` |
| `on_widget_click(..., **selector)` | Нажатие на любой подходящий виджет | `replace=True` |
| `on_key(sequence, ...)` | Сочетание клавиш, можно только при фокусе в элементе | `replace=True` |
| `on_compose_change(...)` | Правка строки ввода пользователем | — |

Изменения внешнего вида без обработчиков: `element().hide()`,
`hide_widgets()`, `set_property()`, `set_colors()`, `decorate_chat()`,
`decorate_message()`, `hide_chats()`, а также `ChatBar`, `Section` и
`Overlay`.

## Qt — `desktop.native`

| Функция | Что даёт |
| --- | --- |
| `on_window(callback)` | Показ и скрытие окон, диалогов и всплывающих меню |
| `connect(widget, signal, callback)` | Любой сигнал Qt любого виджета |
| `await methods(widget)` | Список сигналов, слотов и методов виджета |
| `await invoke(widget, name, *args)` | Вызов слота или invokable-метода |

Имена классов, сигналов и слотов — внутренние имена Telegram и Qt; они
могут меняться между версиями Telegram. Где хватает `desktop.ui`, лучше
использовать его.

## Чего пока нет

- Перехвата отрисовки, кроме декораций строк чатов и сообщений.
- Перехвата событий клавиатуры и мыши, кроме нажатий и сочетаний.

## События реакций, прочтения и рабочего стола

Регистрация через `self.subscribe(name, callback)` возвращает объект с методом
`cancel()`. Обработчик получает `desktop.models.Event` с `account_id`. Таблица
описывает дополнительные поля. `chat_id` использует представление `PeerId`
клиента. У обычного `updateReadMessagesContents` Telegram не указывает чат.

| Имя | Когда приходит и что содержит |
| --- | --- |
| `reaction_changed` | Telegram прислал `updateMessageReactions`. В `message_ids` находится ID сообщения, в `update.reactions` доступен типизированный TL-объект с результатом. |
| `messages_read` | Входящая или исходящая отметка прочтения истории, обсуждения, монофорума или содержимого отдельных сообщений. `update.constructor_name` определяет вид отметки и поля `max_id`, `read_max_id` или `messages`. |
| `topic_changed` | Обновление редактирования или закрепления темы форума либо новое сервисное сообщение о создании или редактировании темы. `update` сохраняет исходный конструктор. |
| `theme_changed` | Изменилась палитра локального клиента. `account_id` соответствует активному аккаунту, `details["night"]` сообщает текущий ночной режим. |
| `selection_changed` | Чат обновил выделение сообщений. `details["items"]` содержит пары `chat_id` (строка), `message_id` (число), в том числе для старой истории мигрировавшей группы. Пустой список означает снятое выделение. `details["window"]` содержит дескриптор доступного окна. |
| `download_started`, `download_finished` | Менеджер загрузок клиента зарегистрировал задание либо готовый файл. Передаются ID чата, ID сообщения и размер в байтах в `details["size"]`. Файловый путь остаётся в клиенте. |

Один и тот же снимок состояния может прийти повторно. При изменении реакции
с одного значения на другое и обратно обработчик получит последнее состояние.
У локальных событий поле `update` равно `None`.

## Фильтры уведомлений рабочего стола

```python
from desktop import notifications

rule = notifications.add_rule(chat=chat, contains="спойлер",
                              replacement="Скрытый спойлер", group_seconds=30)
# Позже, например при смене настроек плагина.
rule.remove()
```

`contains` ищет подстроку в доступном для показа тексте без учёта регистра.
`replacement` задаёт текст баннера, `hide=True` пропускает баннер. При
`group_seconds` от 1 до 3600 клиент показывает первый подходящий баннер и
объединяет следующие за этот интервал с первым, без отдельного счётчика.
Интервал ведётся раздельно для аккаунта, чата, темы и поддиалога.
Пропущенный `chat` распространяет правило на все аккаунты.
Правило скрытия имеет преимущество. Из подходящих замен клиент выбирает
наибольший `priority` (от −10000 до 10000), при равенстве порядок задают
идентификаторы экземпляра плагина и правила.

Правила действуют на баннеры обычных сообщений с доступным предпросмотром.
Предпросмотр проверяется клиентом непосредственно перед выводом. Закрытая
сессия, заблокированный экран, скрытый предпросмотр и уведомления с кодом
входа сохраняют штатное поведение. Спойлеры скрываются до сравнения.
Звуки, значки непрочитанного, реакции и штатные сгруппированные пересылки
обрабатываются отдельно. Правила принадлежат экземпляру плагина и удаляются
при его выключении. Клиент применяет их без вызова Python при показе баннера.
